- 设备分配指<font color="#c0504d">根据用户的 I/O 请求分配所需的设备</font>
- 计算机系统为每台设备确定一个<font color="#c0504d">设备的绝对号</font>以便区分和识别设备

### 设备分配的策略

| | |
|---|---|
|分配的原则|- <font color="#c0504d">设备固有属性</font>决定了设备的使用方式（充分发挥设备的使用效率，尽可能让设备忙碌）<br>- <font color="#c0504d">设备独立性</font>可以提高设备分配的灵活性和设备的利用率（设备独立性是指用户使用设备的透明性，即用户程序与实际使用的物理设备无关）<br>- <font color="#c0504d">设备安全性</font>可以保证分配设备时不会导致永久阻塞（要避免造成进程死锁）|
|设备分配的方式|- <font color="#c0504d">静态分配</font> → 对独占设备的分配 → 在作业执行前分配 → 不会出现死锁 → 设备的使用率低<br>- <font color="#c0504d">动态分配</font> → 在进程执行中分配，通过系统调用发送请求，根据具体策略分配设备 → 分配算法不好时会出现死锁 → 设备利用率高|
|设备分配算法|先请求先分配，优先级高者分配。。。。(类比调度算法)|

### 设备分配的安全性

| | |
|---|---|
|<font color="#8064a2">定义</font>|- 设备分配安全性是指设备分配中应防止发生进程死锁|
|<font color="#8064a2">安全分配方式</font>|- 为进程分配一个设备后就将该进程阻塞，本次I/O完成后才将进程唤醒<br>- 安全分配方式在一个时间段内每个进程只能使用一个设备。<br>- <font color="#c0504d">优点</font>：破坏了请求等待条件，不会死锁。<br>- <font color="#c0504d">缺点</font>：对于一个进程来说，CPU和I/O设备只能串行工作，系统资源利用率低。|
|<font color="#8064a2">不安全分配方式</font>|- 进程发出I/O请求后，系统为其分配I/O设备，进程可继续执行，之后还可以发出新的I/O请求，只有某个I/O请求得不到满足时才将进程阻塞<br>- 不安全分配方式一个进程可以同时使用多个设备<br>- <font color="#c0504d">优点</font>：进程的计算任务和I/O任务可以并行处理，使进程推进<br>- <font color="#c0504d">缺点</font>：有可能发生死锁。|

### 逻辑设备名到物理设备名的映射

|   |   |
|---|---|
|目的|- 为了提高设备分配的灵活性和利用率 → 分别实现I/O重定向 → 所有引入了设备独立性|
|定义|- <font color="#c0504d">设备独立性</font>：指应用程序独立于具体使用的物理设备/用户在编程序时使用的设备与实际设备无关<br>- <font color="#c0504d">逻辑设备表LUT</font>：将逻辑设备名映射为物理设备名<br>- <font color="#c0504d">LUT表项包括</font>：逻辑设备名，物理设备名，设备驱动程序入口地址|
|分类|两种方式设置逻辑设备表<br>1. 整个系统只设置一张LUT → 适用于单用户系统<br>2. 每个用户设置一张LUT → 用户登陆时，系统为用户建立一个进程，同时建立一张LUT|
|好处|- 方便用户编程<br>- 使程序运行不受具体机器环境的限制<br>- 便于程序移植|
