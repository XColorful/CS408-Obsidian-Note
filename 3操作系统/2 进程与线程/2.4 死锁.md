## 死锁的概念

### 死锁的定义

- 死锁是多个进程因为竞争资源而造成的一种互相等待
- <font color="#9bbb59">死锁的充分条件</font>：资源分配图中每种资源只有一个，又出现了环路

### 死锁与饥饿

| | |
|---|---|
|<font color="#c0504d">定义</font>|- 死锁 = 两个或多个进程无限地等待一个事件，而该事件只能由这些等待进程之一来产生<br>- 饥饿/无限期阻塞 = 进程在信号量内无穷等待的情况|
|<font color="#c0504d">差别</font>|- 饥饿并不代表系统一定会死锁，但至少有一个进程的执行被无限期推迟<br>- 进入饥饿的状态进程可以只有一个，但是进入死锁状态的进程必须大于等于2个<br>- 处于饥饿状态的进程可以是一个就绪进程，但是死锁状态的进程必定是阻塞进程|

### 死锁产生的原因

| | |
|---|---|
|1.<font color="#8064a2">系统资源的竞争</font>【空间上】|- 系统中不可剥夺资源不足以满足多个进程<br>- 只有对不可剥夺资源(如磁带机，打印机)的竞争才可能产生死锁|
|2.<font color="#8064a2">进程推进顺序非法</font>【时间上】|- 进程运行时，请求和释放资源的顺序不当<br>- 系统对独占资源分配不当|

### 死锁产生的必要条件

- 以下👇四个条件都要满足才会出现死锁

| | |
|---|---|
|<font color="#8064a2">互斥条件</font>|- 多个线程不能同时使用同一个资源|
|<font color="#8064a2">不剥夺条件</font>|- 进程A已经拥有资源1，在自己使用完之前不能被其他进程获取|
|<font color="#8064a2">请求并保持条件</font>|- 进程A已经有资源1，想申请资源2，但是资源2被进程B持有，进程A处于等待状态，但是进程A不释放资源1|
|<font color="#8064a2">循环等待条件</font>|- 两个线程获取资源的顺序构成了环形链|
