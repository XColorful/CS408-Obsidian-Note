### 进程的控制结构/数据结构

- 进程的控制结构 = PCB + 程序段 + 数据段

|   |   |
|---|---|
|1. <font color="#8064a2">PCB</font>|- PCB 是进程存在的唯一标识<br>- 一个进程的存在，必然会有一个 PCB，如果进程消失了，那么 PCB 也会随之消失|
|<font color="#8064a2">PCB包含什么信息</font>?|![[PCB包含的信息]]|
|<font color="#8064a2">如何组织PCB</font>?||
|2. <font color="#8064a2">程序段</font>|- 能被进程调度程序调度到CPU执行的程序代码段<br>- 程序可以被多个进程共享，即<font color="#4f81bd">多个进程可以运行同一个程序</font>|
|3. <font color="#8064a2">数据段</font>|- 可以是进程对应的程序加工处理的原始数据<br>- 可以是程序执行时产生的中间或最终结果|

### 进程的控制

| |<font color="#8064a2">定义和过程</font>|<font color="#8064a2">对应事件</font>|
|---|---|---|
|<font color="#8064a2">创建</font>|- 允许一个进程创建另一个进程<br>- 允许子进程继承父进程所拥有的资源<br>![[创建进程的过程]]|1. 终端登陆系统，作业调度<br>2. 系统提供服务<br>3. 用户程序的应用<br><br>📢设备分配不需要创建进程|
|<font color="#8064a2">终止</font>|- 有 3 种终止方式：正常结束、异常结束以及外界干预<br>- 当子进程被终止时，其在父进程处继承的资源应当还给父进程<br>- 当父进程被终止时，该父进程的子进程就变为孤儿进程<br>![[终止进程的过程]]|1. 正常结束<br>2. 异常结束<br>3. 外界干预|
|<font color="#8064a2">阻塞</font>|- 当进程需要等待某一事件完成时，它可以调用阻塞语句把自己阻塞等待<br>- 一旦被阻塞等待，只能由另一个进程唤醒<br>![[阻塞进程的过程]]|1. 请求系统资源失败<br>2. 等待某种操作的完成<br>3. 新数据尚未到达或无新任务可做|
|<font color="#8064a2">唤醒</font>|- 进程由「运行」转变为「阻塞」状态是由于进程必须等待某一事件的完成<br>- 处于阻塞状态的进程是绝对不可能叫醒自己<br>- 如果某进程正在等待 I/O 事件，需由别的进程发消息给它<br>- 只有当该进程所期待的事件出现时，才由发现者进程用唤醒语句叫醒它<br>![[唤醒进程的过程]]|1. 释放该I/O设备的进程<br>2. 提供数据的进程|
